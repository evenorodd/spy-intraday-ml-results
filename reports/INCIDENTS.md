# Retained incidents and development changes

This summary of principal incidents accompanies the scientific results. Repairs did not erase original
failures or change the completed studies' reported outcomes. Historical evidence,
approvals and journals remain retained privately with the project registry.
This public summary is not a complete export of that private incident ledger.

| Incident or development | Resolution / retained limitation |
|---|---|
| Stage 2A reducer counted its own running history | A separately approved reducer-only recovery reused 50 successful jobs and retained original failed run `3701b0a1-29df-4ad5-8c63-b8d67ce28497` |
| Stage 2B registration compared a Python date through a JSON serializer | A bounded date-serialization repair was prepared; the traceback and original registration evidence were retained |
| Stage 2C development capacity remapping | A separately approved eight-fold development mapping passed count/variance planning only; this did not establish real-study or full-procedure power |
| Stage 2D checkpoint inventory rejected its own successful build checkpoint | A separately approved repair reused build `e02606ba-8fd5-4ccc-9b00-88b20de77c7e` and continued unstarted jobs; the build was not repeated |
| Stage 2D positive cases collided on exact experiment registration keys | A separately approved metadata repair appended existing case keys to 200 unstarted positive-case families; all 60 completed jobs and the failed continuation journal were retained |
| Binary conditional oracle cutoff admitted inactive-score ties | Thirteen artificial tests reproduced the corner case and matched 219 frozen-function binary vectors; a future-only stop guard was tested, with no retrospective edit to Stage 2D/2E |
| Positive-control economics were checked after the large fitting campaign | Stage 2E documented the mismatch; the original Stage 2D non-pass remained unchanged; economic checks should have preceded fitting |

The registration-key repair retained the original unique registration index,
scientific job IDs, model parameters, seeds, artifacts and null-first rule.
Its remaining limits were 19,200 outer prediction fits and 32,000 estimator fit
calls. This was explicit incident continuation, not an automatic retry policy.

The publication itself runs no database migration, scientific registration,
dataset construction, fitting or continuation. It makes no claim that the
private registry was reopened or administratively marked closed by this release.
